# G0 safety validation — 2026-09-06

## Scope

이 검증은 event-driven placement 기준선을 릴리스하기 전에 세 가지 데이터 안전 경계를
고정한다.

- copy 후 checksum dry-run이 실제 변경 목록을 검사해야 한다.
- reservation ConfigMap과 `ShiftPVVolume` 중 하나만 삭제된 재시도도 끝까지 수렴해야 한다.
- destination이 status에 기록되기 전에 스케줄된 placement reservation은 source recovery를
  막지 않아야 한다.

## Regression locks

copy Job은 `rsync -a --checksum --delete --dry-run --itemize-changes`의 출력이 비어 있을
때만 move marker를 쓴다. 같은 크기의 다른 내용, destination 누락 파일과 destination의
추가 파일은 모두 non-empty diff로 검출했고, 동일한 tree만 empty diff를 반환했다.

`DeleteVolume`은 reservation과 Volume CR을 독립적으로 읽는다. ConfigMap 삭제 뒤 Volume CR
삭제 응답이 실패한 경우와, 실제 CR 삭제 뒤 timeout 응답만 유실된 경우를 각각 재시도해
멱등 종료했다. 두 기록이 모두 없을 때만 이미 완료된 삭제로 판단한다.

첫 source-node restart 실행은 placement reservation이 destination에 스케줄됐지만
`status.destinationNode`가 아직 비어 있는 경계에서 `Quiescing` 고착을 발견했다. reservation은
Move UID, 결정적 이름과 role을 검증한 뒤 node와 무관하게 제거하도록 수정했다. volume을
만지는 다른 helper는 계속 기록된 source/destination 밖의 node에서 거부한다. 같은 실패
케이스와 전체 여섯 node-restart matrix를 새 클러스터에서 다시 실행해 통과했다.

최종 review에서는 terminating reservation을 이미 삭제된 것으로 보던 코드와 “삭제 관찰 뒤
release” spec의 차이를 발견했다. live Pod는 `deletionTimestamp`가 있어도 reservation으로
간주하고 실제 `NotFound` 뒤에만 workload Hold를 해제하도록 고정했다. 새 unit test와 전체
mobility Kind 재실행에서 termination grace 동안 Hold가 유지되고 이후 정상 수렴함을 확인했다.

## Runtime result

다음 검증이 모두 exit zero로 끝났고 생성한 Kind 클러스터와 임시 pool은 제거됐다.

```bash
make verify
CLUSTER_NAME=shiftpv-g0-mobility ./test/e2e/kind/mobility/run.sh
CLUSTER_NAME=shiftpv-g0-restarts-all \
  MOBILITY_NODE_RESTARTS_ONLY=1 ./test/e2e/kind/run.sh
CLUSTER_NAME=shiftpv-g0-basic ./test/e2e/kind/run.sh
CLUSTER_NAME=shiftpv-g0-argocd ./test/e2e/kind/argocd/run.sh
```

`make verify`는 race test, 83.1% statement coverage, vet, build, release fixture,
shellcheck, Helm lint와 deterministic rendering을 통과했다. Kind에서는 다음을 확인했다.

- copy/preflight/cleanup failure와 명시적 recovery, 정상 이동, 세 commit 경계의 Controller 재시작;
- source, pre-copy destination, Copying source/destination, Promoting destination,
  committed destination의 실제 node container stop/start;
- 기본 StorageClass provision/publish, Controller와 Node Plugin 교체, Retain uninstall/reinstall;
- ENOSPC/read-only partial staging 복구와 기존 default StorageClass 공존;
- Argo CD의 허용된 Application 삭제, dependency가 있는 PreDelete 차단과 blocker 제거 후 자동 수렴.

릴리스 후보 버전은 chart `0.1.3`, controller `0.1.4`, node `0.1.1`이다. 공개 artifact lock은
실제 publication 전까지 마지막 공개 조합인 chart `0.1.2`, controller `0.1.3`, node `0.1.1`을
유지한다.

## Boundary

이 결과는 Kind의 directory-backed mounted filesystem과 현재 지원 scheduling shape에 대한
증거다. 물리 디스크 crash consistency, permanent source loss, replication, backup, hard quota와
production network/disk 성능은 검증하지 않는다.
